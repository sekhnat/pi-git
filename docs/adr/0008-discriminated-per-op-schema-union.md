# Discriminated per-op schema union, adopted on verified pi + pi-fabric support

The `github` tool's parameter schema is a `Type.Union` of 11 per-op objects — an `op` literal plus exactly that op's parameters (`search_code` drops `since`/`until`, which its runtime rejects; `search_repos` drops `repo`, which it ignores) — tightening `file_read.path`, `pr_checkout.pr`, and `search_code.query` to required, and carrying `format` on every variant. The dispatch `switch` stays exhaustive (`never` default); executors consume the flat `GithubInput` interface, which every union variant is assignable to.

Adopted because the spike (`.scratch/fabric-compat/spike-report.md`, GO) verified each leg with recorded evidence: pi validates a top-level `anyOf` and rejects missing required args in live sessions; pi-fabric's schema channel surfaces the union intact; the captured-type generator renders it as a real 11-member TypeScript union (`tsc` flags exactly the missing-required calls); the slim union stays under the capture-size caps. Rejected: keeping every parameter optional for every op (missing required args could only fail inside executors), and a fully-described union (5654 chars exceeds the 4096-char captured-source cap, where pi-fabric silently falls back to an untyped declaration — per-parameter descriptions therefore live only in the tool description).

Recorded nuance: on pi-fabric's main `fabric_exec` path the TS assignability diagnostics (TS2345/2339) are currently advisory — missing required args fail at **dispatch-time schema validation, before the executor runs** (verified live), and only Jev programs enforce them at the type-check today. The upstream draft in the spike report asks pi-fabric to expose type-correctness enforcement; until then the union's requiredness is enforced one step later than the ideal but strictly earlier than the flat schema's in-executor checks. Prompt bloat was measured, not guessed: +1600 chars of schema JSON for this tool — modest against the system prompt and not fallback grounds.
