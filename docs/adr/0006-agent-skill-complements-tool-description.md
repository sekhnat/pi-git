# Agent skill complements, never duplicates, the tool description

The package ships a `pi-git` skill that carries workflow-level guidance — the PR checkout → worktree → push/create flow, search-qualifier syntax pointer, `run_watch` polling semantics, worktree expectations, the `/commit` flags block, and fabric-exec steering (`extensions.github(...)` over shell `gh`, `tools.list` for the live schema, `file_read` over `curl`/`wget`). Op tables and per-op parameter rules stay **only** in the `github` tool description: the skill points at it as the source of truth rather than restating it, so per-op facts are single-sourced and cannot drift apart. Rejected: a skill that mirrors the tool description (two copies of every parameter rule, guaranteed divergence).

Deviation from the original plan: the conventional `skills/` directory is **not** auto-discovered for this package, because a `pi` manifest is present (it exists for `extensions`), and a manifest switches the package to explicit resource declarations. `package.json` therefore declares `"pi": { "skills": ["./skills"] }`. Smoke-verified via the pi resource loader (`DefaultResourceLoader` with the package as an additional extension path): without the entry the skill is absent; with it, `pi-git` is listed with valid frontmatter and no diagnostics.
